# 文档维护规则

规则文件只保留长期有效的约束和入口；详细内容按主题维护，避免多份规格互相冲突。

## 内容放在哪里

| 内容 | 位置 |
| --- | --- |
| 仓库地图与通用底线 | 根目录 `AGENTS.md` |
| 子项目约束与代码入口 | 各子项目 `AGENTS.md` |
| 启动、开发与测试 | 各子项目 `README.md` |
| 产品需求 | `docs/prd/<版本>/` |
| 架构、接口与数据设计 | `docs/技术方案/` 对应版本与模块 |
| 验收、风险与实施进度 | 对应 `plan.md`；独立 session 记录机制尚未建立 |
| 部署操作 | 各子项目 `deploy-prod.md` |

## 写作与更新

- PRD、技术方案用大白话：先说问题和用户可见变化，再说必要实现；术语要解释。
- 流程、模块关系和状态变化配 Mermaid 或示意图；字段映射和差异用表格，图旁简短解释。
- PRD 建议顺序：问题与目标 → 用户流程 → 范围与规则 → 验收示例。
- 技术方案建议顺序：解决办法 → 架构或数据流图 → 关键取舍 → 验证与风险。
- 架构或模块职责变化，在同次交付中更新对应架构图、规格和入口链接；只有导航变化才修改 AGENTS.md。
- 接口或模型变化核对 BE、FE、Agent 和迁移的影响；发现代码与规格不一致时明确记录。
- 记录区分目标、实现、测试和实际验收，不把未执行检查写成通过。
- 历史版本保留背景和证据，不能作为当前运行环境或数据库版本的保证。
