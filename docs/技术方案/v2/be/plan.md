# JINGPO 后端 V2 · 分步实施计划

> 2026-09-30 · 实施与验证记录。依据 [V2 PRD](../../../prd/v2/JINGPO-logistics-system-v2.md) 和 [spec](spec.md)。

## 1. 实施原则

V2 先在固定 A/B/C、AB/BC 网络上完成模型替换。各步在隔离分支和测试库验证；阶段与事件切换相关步骤完成前，不把中间状态部署到共享环境。代码、迁移和客户端契约必须作为一次可运行的切换交付。使用独立 PostgreSQL 测试库及 V1 数据副本，开发库不作为清理型测试库。步骤可以继续拆小，完成当前步骤并记录验证证据后再推进下一步。

本轮在工作区同步修改 `be`、`fe`、`agent`；已有 V1 开发库没有执行 V2 迁移。验证使用独立的 `_test` 数据库。

## 4. 可重复验证

在已初始化 A/B/C、AB/BC 和演示时钟的隔离测试库运行：

```bash
cd be
DATABASE_URL='postgresql+psycopg:///jingpo_logistics_v2_test' RUN_V2_MIGRATION_TESTS=1 ./.venv/bin/python -m unittest discover -s tests -v
DATABASE_URL='postgresql+psycopg:///jingpo_logistics_v2_test' ./.venv/bin/python -m alembic check
cd ../agent && ./.venv/bin/python -m unittest discover -s tests -q
cd ../fe && npm run build
```

2026-09-30 结果：BE 6/6（4 项业务测试、2 项迁移演练）、Agent 20/20、前端构建通过、迁移模型无差异。前端构建仍有大包体积提示，未阻止构建。迁移演练需要 CREATE DATABASE 权限，自动创建并删除独立临时测试库；不设置 `RUN_V2_MIGRATION_TESTS=1` 会跳过两项迁移测试。

### 页面与真实接口验证

使用独立 V2 测试后端 `127.0.0.1:8765`、前端 `127.0.0.1:5174` 和原生 Chrome 操作，未使用开发库。订单 `ORD-000023`、运单 `SHP-000023`、AB 任务 `TRIP-000020`、BC 任务 `TRIP-000021` 完成：

- 创建订单、运单；修改运单收件地址，订单保留原下单地址，两类地址在详情中分别展示。
- 揽收后没有扫描站点；独立 A 入站后成为在站。未揽收时入站按钮禁用，B 站不能开始派送。
- 创建 AB 后运单仍在 A、任务待发车；发车后显示 A→B 运输中、最后扫描 A。推进演示时钟两小时，AB 超时 60 分钟；到达后记录历史晚到 60 分钟，运单在 B。
- 创建 BC、发车、到 C、派送、签收；任务当前线路和站点正确。签收后订单完成，详情保留全部 9 条轨迹，包含 3 条 ARRIVE 和 2 条 DEPART。
- 通用阶段筛选「在站」成功，非法操作按钮禁用，签收后所有物流操作按钮禁用。

走查发现任务表单提交日期实际为字符串，旧代码调用 `.format()` 导致失败。现已明确使用字符串提交，并附 `+08:00` 时区；修复后 AB、BC 任务均由页面创建成功。

## 5. 发布注意

产品 V2 沿用 `/api/v1` 路径，但阶段和事件取值发生变化；旧版前端、Agent 或其他客户端需要随服务端一起升级。升级真实数据库前先备份并在副本演练。V2 通用状态不等于站点和线路可配置，当前仍只接受 A/B/C、AB/BC。
