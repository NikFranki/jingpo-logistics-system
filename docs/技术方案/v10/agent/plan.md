## 2. 验证清单

| 范围 | 核对内容 |
| --- | --- |
| 查全 | 多页对象集合一致；同运单多次更正计数正确；不遗漏后续页或重复对象 |
| 关联 | 订单→运单→任务方向正确；共享成员、计划、当前和已解除关联不混淆 |
| 依据 | 对象类型/ID/状态/时间能与授权源记录逐项对照；无依据不能肯定 |
| 不完整 | HTTP/工具/时间预算用尽、响应截断、部分失败均标清范围；不把未完成答成没有 |
| 权限 | 普通用户只查自身数据；公司级范围正确；降权、缓存重放与追问沿用 V8 保护 |
| 回归 | 会话隔离、SSE、断线恢复、只读工具白名单及现有预算保持有效 |
| 真实模型 | 每轮查全率及事实正确率至少 95%；状态混淆、越权与无依据肯定为零；所有设计的未完成案例有提示 |

真实模型验收尚未通过：每题目前都按关键项计分，因此严格匹配失败会阻止验收。`deepseek-full-1` 的 BIZ-02 答案 `2026-10-17T08:00:00Z` 与预期 `2026-10-17 08:00` 表示同一 UTC 时间；DeepSeek 后续轮的 HOLD-05 明确说本人可见范围内未找到，并说明不能据此断定对象不存在。应修正评测条件以识别等价时间格式和表述，再重新评分现有报告。Qwen 报错原因为 `AllocationQuota.FreeTierOnly`，表示免费额度耗尽；评测真实请求会消耗模型额度，`--preflight` 与单元测试不会。

## 3. 三端影响与边界

- Agent：先补评测，再按失败原因改查询组织、覆盖记录与回答规则。
- BE：复用现有订单详情关联和更正审计接口；本轮无 BE 代码、迁移或权限改动。
- FE：请求无需增加评测或预算参数；只有确定新增响应展示时再改客户端。
- 部署：沿用 V9，当前单实例内存会话保持；持久会话、多实例及费用预算后排。
