## 1. 怎么推进

先建立无任务写入的完整计划预览，再实现每站时间审核和一次确认生成全部任务；同时拆分未来关联与当前执行占用。到站只激活已有任务。正常验收必须证明：确认 A→B→C 后，两段立刻都有编号，后段到站前不能发车，到站后任务数量不增加。

```mermaid
flowchart LR
    D[修订 PRD、spec、plan 和术语] --> M[等待状态、依赖关联与迁移]
    M --> P[参考耗时与全程预览]
    P --> C[逐站编辑、人工确认和全段任务生成]
    C --> A[首站入站、中转到达激活]
    A --> R[延误预测、共享任务与未来重确认]
    R --> V[HTTP、并发、故障与旧数据回归]
    V --> H[发布与 FE/Agent 交接]
```

## 3. 当前代码差距与实施入口

| 位置 | 当前 V6 行为 | V7 改动 |
| --- | --- | --- |
| network、planning schemas/service | 无参考耗时；方案保存完整 route_ids | 时长和方案覆盖；作为预览参考，允许人工审核时间偏差 |
| scheduling（拟新增） | 当前没有此模块 | 预览/确认、完整时间版本、所有分段任务编排、滚动预测 |
| models TaskShipment 索引 | released_at 为空即唯一运单占用 | PLANNED/ACTIVE/RELEASED；同运单多未来关联、单 ACTIVE、同段单未结束安排 |
| logistics_types、task 状态约束 | 只有待发车、运输中、到达、取消 | 待首站入站、待前段到达及成员就绪校验 |
| planning active_task/leg_state/path_body | 按未释放关联取当前任务，不识别未来任务 | 当前只取 ACTIVE，未来段展示 PLANNED 和已有 task_id |
| shipments 首站 ARRIVE | 首站实际入站后自动绑定唯一方案 | 未确认时生成推荐信息；已有确认计划时验证起点并激活首段，禁止绕过审核生成任务 |
| transport create/arrive | 当前逐段创建，到达释放旧占用 | 确认时生成全链；到达释放 ACTIVE 后激活已有 PLANNED，依赖全体校验 |
| transport cancel | 仅取消待发车整批任务并释放占用 | 两种等待状态可取消，审核共享及下游影响，失效关联并要求重新确认 |
| shipments destination/path update | 只检查当前占用和 V6 路径冻结 | 同时检查未来预留；更正前审核解除，路线时间一并重新确认 |
| 任务/运单详情与 allowed_actions | 无审核时间表或等待前段资格 | 计划/预测/实际及全部任务、执行/取消资格与影响名单 |
| simulation advance | 更新时间和日志 | 保持事实流程，预测读取时钟，计划时间不自动修改 |

开发库当前使用 V6；V7 文档不表示数据库已有这些结构。已有 BE/FE 修改保留，实施须以当前工作区为准。

## 5. 本次修订记录

用户要求采用指定 thread 的新讨论。会话读取接口返回未加载，随后从本地该 thread 的用户提问记录读到“人工确认”“每站可改时间”“切换路线同步预览”等需求；用户提供截图补全最终结论：人工确认后自动生成各段任务，后段等待货物到站才能发车。
