## 1. 依据与协作方式

依据 [spec.md](spec.md) 与 [Agent V1 技术方案](agent-v1技术方案.md)。使用 LangGraph + LangChain 组件，模型先接 ChatDeepSeek，独立模型创建入口支持后续替换。

- 使用 A01～A22 编号，区别于已完成的 BE S01～S22。
- 每次只推进一个小步；仍过大时拆为 Axx.1、Axx.2。
- 2026-09-29 起由助手主导写入与必要验证，用户负责 review；每次推进当前步骤，review 后再继续。
- 不一次性生成 Agent，不提前创建后续模块，不重复验收已通过的 BE 功能。
- 只读查询使用已有 BE 数据；缺少特殊状态时可用受控模拟，明确标注证据类型，不让 Agent 写入或清理业务数据。
- 新增依赖时核对官方接口、固定已验证版本；密钥由用户在本地配置，不粘贴进对话或提交到 Git。

## 2. 必须保持的执行规则

1. 每条用户消息最多 5 次模型请求。每次按相同规则处理，返回回答或澄清即可提前结束。
2. 第 5 次若要求工具，仍执行合法且预算允许的工具；完成后停止，不调用第 6 次模型，固定提示查询未完成。
3. 模型请求尝试开始前计数；SDK 自动重试关闭。工具、HTTP 与时间预算分别计算。
4. 第 5 次不切换提示词、不移除工具、不额外发起总结调用。
5. 工具请求与 ToolMessage 必须完整配对；失败、预算拒绝、中断后的下一轮都保持合法消息结构。
6. 追问重置本轮预算，记忆仅帮助定位对象；当前业务状态重新查 BE。
