# JINGPO 鲸破 · PRD V2

> 2026-09-29 · 草案。V2 聚焦通用物流状态与轨迹事件；本文定义目标行为，不表示已经实现。

依据：[V1 PRD](../v1/JINGPO-logistics-system-v1.md) 与已确认的业务约定：揽收和首站入站分开；运单地址修改不回写订单。

## 1. 目标

让一张运单的阶段只描述它处于什么环节，具体在哪个站、走哪段线路由站点和运输任务说明。用户仍能完整演示卖家 → 揽收 → A → B → C → 派送 → 签收，但界面和轨迹不再依赖 `AT_A`、`IN_TRANSIT_AB`、`ARRIVE_B` 等带地点的状态或事件名。

V2 完成后，运单在 A、B、C 站都显示同一种“在站”阶段，在 AB、BC 两段运输中都显示同一种“运输中”阶段；页面同时展示具体站点或运输起终点。这为后续版本配置站点与线路打基础，但 V2 本身仍使用固定 A/B/C、AB/BC 和区域 Z。

## 2. 范围

| V2 纳入 | 后续版本再做 |
| --- | --- |
| 通用运单阶段、通用轨迹事件及前后端展示 | 站点和线路的新增、编辑、停用 |
| 揽收与首次入站分开；任务到达与终点入站合并 | 车辆到达但包裹尚未入站的中间过程 |
| 历史数据迁移；现有前端和只读 Agent 的同步适配 | 外部扫描设备接入、乱序事件处理 |
| 维持 V1 的事务、防重、延误和地址规则 | 智能路径选择、异常工单、权限、多租户 |

## 3. 业务术语与规则

**订单**保存下单信息。创建运单时复制收发地址到运单；创建运单后修改运单地址，只改变履约地址并保留变更记录，不回写订单。

**揽收**表示从发件人处接收货物。揽收后尚未证明货物已经到 A 站；首次入站必须有独立操作和轨迹。

**在站**表示货物已经进入某站。运单记录该站点；V2 首次入站是 A，AB 到达后是 B，BC 到达后是 C。

**运输中**表示某个关联运输任务已经发车且尚未到达。运单最后扫描站点仍是起点，它不是实时物理位置；起点和终点从该任务所用线路取得。

**发车**是一个发生在特定时刻的动作：任务从待发车变为运输中，关联运单从在站变为运输中，并追加 `DEPART` 轨迹。运单没有持续停留在“发车”这一阶段；发车时间从任务和轨迹查询。

**任务到达**在 V2 继续代表任务及全部关联运单一次性到达并入站。到达失败时任何运单都不能只更新一半。

## 4. 用户可见流程

1. 创建订单和运单；运单待揽收，轨迹显示运单创建。
2. 揽收；运单显示已揽收，尚无入站站点。
3. 扫描进入 A；运单显示“在 A 站”，轨迹显示“到达 A 站”。
4. 创建 AB 任务；运单仍在 A，但显示已被待发车任务占用。
5. AB 发车；运单显示“运输中 · A → B”，最后扫描 A。
6. AB 到达；运单显示“在 B 站”，轨迹显示到达 B 并关联 AB 任务。
7. BC 发车、到达同理；到达 C 后可开始派送，再签收。

页面的状态筛选按通用阶段进行；位置和线路另行展示。轨迹以统一的 `ARRIVE`、`DEPART` 类型配合站点、任务信息生成自然语言，不把编码直接显示给用户。

## 5. 完成标准

- 新建运单与 V1 历史运单都能按新模型查询，历史轨迹的时间、顺序和关联任务不丢失。
- 正常链路、禁止跳站、候选运单选择、重复操作、并发占用、任务批量到达和 AB 延误仍可复现。
- 运单阶段和轨迹事件类型不再包含 A/B/C 或 AB/BC；具体地点从关联数据取得。
- 前端与只读 Agent 能解释“在站”“运输中”和最后扫描站点，且不把最后扫描站点说成实时位置。
- V1 已确认的订单地址与运单地址分离规则保持有效。
